# 光印的自由创作、风格库与模板互换研究

2026 年 11 月 25 日。项目基准是已发布的 v0.0.2。本次核对了 Android 与 CLI 源码、同类产品的开发者说明、文件规范，以及两个开源项目共 14 份实际模板。竞品功能依据开发者公开资料，模板样本做了文件结构检查。本文提出的路线和验收指标用于后续设计。当前开发版实际接受的文件见[格式说明](../docs/preset-format.md)。[v0.0.2 源码](https://github.com/zhizhiheng/kaiprint/tree/v0.0.2)

**最值得解决的任务是让摄影师完成一次设计后，换照片、换相机、换设备仍能继续改。** 例如，用 ZR 拍一张横图做展签，在左侧放机型标志，右侧放镜头和曝光，底下署名。第二张换成富士竖图时，机型和参数应自动更新。第三张是胶片扫描件时，摄影师应能补一个镜头名，并让空参数行自行收起。朋友收到 .kaiphoto 后，应能更换署名、挪动标志、保存自己的版本。

## 14 份实际模板的结构检查

选取 darktable 5.6.0 的 data/watermarks 下全部 7 个 SVG，与 semi-utils 固定提交的 static 下全部 7 个 JSON。SVG 按 XML 元素名称计数，并提取美元符号加括号形式的占位符。JSON 按文件提取处理器名称与 EXIF 字段表达式。统计范围限定于这两个项目自带的模板。[darktable 样本目录](https://github.com/darktable-org/darktable/tree/3c17b2976793303c186a5f64e8c9635ecf8b15d3/data/watermarks) · [semi-utils 样本目录](https://github.com/leslievan/semi-utils/tree/b1cf1ce655e9452a78a88f465d4387f84cf6740e/static)

- **SVG 需要核对绘图结构和动态字段。** 7 份 darktable SVG 中有 6 份包含占位符。simple-text.svg 只有 1 个文字元素，适合验证文字与字体绑定。metadata-template.svg 则含 28 个文字元素、48 个路径、33 个滤镜定义，以及旧式 EXIF_ISO、MODEL 等变量。滤镜数统计的是声明，在成片中可见的数量需要另外验证。一个能打开简单样本的导入器，仍可能把复杂样本中的变量原样印出来。[简单样本](https://github.com/darktable-org/darktable/blob/3c17b2976793303c186a5f64e8c9635ecf8b15d3/data/watermarks/simple-text.svg) · [复杂样本](https://github.com/darktable-org/darktable/blob/3c17b2976793303c186a5f64e8c9635ecf8b15d3/data/watermarks/metadata-template.svg)
- **相同 JSON 后缀里可以装不同的处理流程。** semi-utils 的 normal1.json 使用两种处理器，负责对齐和文字。nikon_blur.json 使用九种，涉及模糊、缩放、裁切、拼接、圆角、投影与富文本。standard1.json 又有日期多字段回退、自动选标和外部字体路径。第一批转换可选常见固定版式和明确的字段表达式。其余处理器列出具体名称，让作者判断能否接受静态装饰。[简单排版](https://github.com/leslievan/semi-utils/blob/b1cf1ce655e9452a78a88f465d4387f84cf6740e/static/normal1.json) · [尼康雾面样本](https://github.com/leslievan/semi-utils/blob/b1cf1ce655e9452a78a88f465d4387f84cf6740e/static/nikon_blur.json) · [标准样本](https://github.com/leslievan/semi-utils/blob/b1cf1ce655e9452a78a88f465d4387f84cf6740e/static/standard1.json)

## 外部格式的导入优先级

下表是设计目标。每种外部格式的读入、编辑与成片结果，应独立验收后再对外声明支持。

| 来源 | 建议导入结果 | 首个验收样例与限制 |
| --- | --- | --- |
| 光印原生 .kaiphoto、历史光印 ZIP 与可识别的原生模板 JSON | 保留边框、图层顺序、位置、文字、动态字段、标志和字体引用。文件格式版本独立于应用版本。 | 保存、导入、改字、换图再保存，核对各层和资源。裸 JSON 缺少外置字体或位图时，应指明受影响的层。原生包可使用示意缩略图，避免传递作者的原照和坐标。[现有归档规范](https://github.com/zhizhiheng/kaiprint/blob/v0.0.2/docs/preset-format.md) |
| 普通 SVG、darktable SVG | 先处理静态装饰素材和能明确映射的文字、变量。可继续缩放的路径和能改字的文本应分别报告。 | 一份样本含原生 text、已转曲字和带蒙版装饰。原生文字可重绑，转曲字保留图形。复杂效果若降级应可见。仅呈现本地静态内容，可参照 W3C 安全静态处理模式。[W3C SVG 处理模型](https://www.w3.org/TR/SVG2/conform.html#secure-static-mode) · [darktable 水印](https://docs.darktable.org/usermanual/5.6/en/module-reference/processing-modules/watermark/) |
| OpenRaster .ora | 建议作为第一种外部分层交换格式。先处理普通叠加的位图层，保留名字、偏移、透明度和可见性，再让作者指定照片位与动态参数。 | 在 Krita 创建半透明印章、装饰层和隐藏层。接收方应能逐层移动、隐藏。Krita 的 ORA 将图层保存为 PNG，原文字需要重建。特殊混合模式应提示影响。[Krita 手册](https://docs.krita.org/en/general_concepts/file_formats/file_ora.html) · [OpenRaster 图层栈](https://www.openraster.org/baseline/layer-stack-spec.html) |
| semi-utils JSON | 按已知处理器和表达式子集转换。尽量保留 EXIF、字号、分隔符与对齐。 | 使用实际开源模板，找到未知处理器、引用字体或外部图片所在位置。展示受影响内容与替代方式。通过已知字段映射实现转换，避免将第三方表达式作为程序执行。[标准模板](https://github.com/leslievan/semi-utils/blob/b1cf1ce655e9452a78a88f465d4387f84cf6740e/static/standard1.json) |
| PSD / PSB | 待独立位图层、分组及蒙版模型成熟，先试读常用像素层与可识别文字。文件包含合成图时可提供平面装饰选项。 | 用中文文字、智能对象、遮罩和缺合成预览的真实文件验收。Adobe 规范分别定义图层通道、附加对象数据和图像数据。不能正确解释内容时，应列出具体图层。[Adobe PSD 规范](https://www.adobe.com/devnet-apps/photoshop/fileformatashtml/) |
| Canva 链接、导出图片或 PDF、Lightroom 显影 XMP | Canva 用户可单独导出装饰，在光印重新绑定参数。Lightroom Develop XMP 属于色调等显影配置，识别后可说明用途。 | PNG 中的文字及作者绑定无法从像素直接恢复。若要直接获取 Canva 云端模板字段，需要另外设计授权接入流程。Lightroom 的文字或图形水印有独立编辑器。[Canva 导出](https://www.canva.dev/docs/apps/rest-apis/reference/exports/create-design-export-job/) · [Lightroom 显影预设](https://helpx.adobe.com/lightroom-classic/desktop/process-and-develop-photos/apply-presets.html) · [Watermark Editor](https://helpx.adobe.com/hk_en/lightroom-classic/desktop/workspace/using-watermark-editor.html) |

导入确认页可以给出类似「2 段文字可改、1 个装饰层已合成、镜头字段需要绑定、缺少字体 A」的结果。可将回读后可改的图层数、仍能随照片变化的字段数、提示过的降级项与样图一起记录。

## 风格库如何做多、做出差异

建议先规划 8 个摄影用途，每个用途设计 3 个结构不同的候选版式。以下 24 个是候选题目，包含已有方向，实际收录数量按通过测试的版式统计。深浅色、厂标款式属于同一版式的选项。每个母版提供可编辑的字体、留白、字段和标志位置。

| 用途 | 三个候选版式 | 可复用的构件 |
| --- | --- | --- |
| 展览与作品集 | 单行展签、左侧题签、双语目录页 | 标题、作者、日期按信息层级排版，长署名可换行 |
| 旅行与街拍 | 地点片注、路线手记、竖幅明信片 | 城市与手填地点、可选日期、作品标题 |
| 器材与技术展示 | 居中铭牌、镜头索引、双栏器材档案 | 逐图选标，镜头全名或手动镜头名称 |
| 风光与色彩 | 横向色谱、竖排色样、宽景雾面展框 | 独立色卡、毛玻璃强度和照片内文字对比度 |
| 胶片与扫描件 | 胶卷编号题签、暗房印样、胶片日期角标 | 手动机身和镜头参数、卷号、日期 |
| 纪实与出版 | 报刊图注、跨页侧注、人物作品说明 | 标题、地点、作者可分别隐藏，长文有独立区域 |
| 电影剧照 | 宽银幕片名、窄边双端片签、竖版演职员题签 | 片名和署名可替换，可选 ZR 或其他机型识别 |
| 工作交付 | 淡角标、通栏审片说明、重复校样水印 | 工作室标、授权说明和重复文字可独立调整 |

用当前照片浏览版式，再按用途、照片内/外、适合竖图、信息密度和所需字体筛选。「我的预设」应能命名、复制、改版、导出、从文件恢复。等文件互换稳定，再考虑作者主页和在线画廊。

## 0.0.3 开发版与下一步取舍

本轮把「从零创作 → 复用 → 分享后再编辑」接进了 Android。可以在自己的照片或内置示例上起稿，把成组的拍摄参数和固定署名分开放置，复制图层，保存原稿或另存副本。22 款内置排版均可修改，空白画布独立计数。手机和桌面共用有版本号的 `.kaiphoto` 文件，Android 负责逐层出图，CLI 提供打包和检查。两份示例分别来自 CLI 与 Android。[八款新增风格的实际成片](../docs/examples/creator-presets.jpg) · [旅途手记](../examples/presets/travel-notebook.kaiphoto) · [旅行明信片](../examples/presets/field-postcard.kaiphoto)

| 建议顺序 | 要解决的拍摄任务 | 完成条件 |
| --- | --- | --- |
| 1. 让一套设计适应不同照片 | 把横幅 ZR 展签套在竖幅人像、长镜头名和无 EXIF 的扫描件上。补上区域内的对齐、间距、换行、空字段折叠策略，提供不同画幅的并排预览。 | 用下节的固定样片逐张核对，照片主体、署名和厂标均可见，空行按作者选择处理。 |
| 2. 让作者维护自己的风格系列 | 把「厂标＋机型＋分隔线」组合并锁定。把字体、色彩和署名做成可复用的设置，让同一系列保留横竖变体。将模板作者、作品摄影师和授权说明分开保存。 | 改工作室署名时能预览影响范围；修改单张照片或派生副本时，原设计保留。 |
| 3. 让外来设计的转换结果可核对 | 优先实现 darktable 常用照片变量与 OpenRaster 独立位图层，并给每层标出动态绑定、固定图形或缺失资源。用同一文件推进 CLI/MCP 成片与 Android 的一致性。 | 用实际样本验证每个适配器，列出保留、合并和需重绑的图层；同一模板在各端的画布尺寸、字段和图层位置可比对。 |

## 建议的验收顺序

1. **从空白完成第一份原创。** 用户用文字、品牌和参数三层完成 ZR 展签，撤销一次误操作，命名保存，离开后继续修改。导入朋友的设计再另存副本。观察能否直接找到空白入口以及选错图层后恢复需要几步。
2. **逐个风格验证换图。** 每个候选版式用横图、竖图、正方形、长镜头名、双语署名、无 EXIF 的固定样片出图。记录遮挡主体、文字截断、标志和文字重叠、空参数栏、对比度不足五类问题。
3. **用干净设备验证交换。** A 机保存带自定义 Logo 和字体的作品，B 机导入并改署名，再导回 A。核对结构、资源引用与可编辑性，允许包内资源重命名。缺字体时记录替代，未知版本应提示所需版本。
4. **用同一文件验证各端。** Android、CLI 和 MCP 对固定模板、同一照片及相同覆盖值给出一致的画布尺寸、图层顺序、字段、可见性和标志身份。字体抗锯齿等渲染差异用导出样图核对。尚未实现的属性列到转换报告。
5. **按真实样本扩展导入范围。** 每个适配器分别记录完整支持、部分支持、无法导入的样本比例与原因。PSD、云端模板和复杂 SVG 各自建立验收资料，以实测的编辑与渲染能力决定公开支持范围。
